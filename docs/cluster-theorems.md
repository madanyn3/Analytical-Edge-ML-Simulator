# Analytical results for the tiled cluster

This document states and proves the analytical results for the synthetic tiled cluster
of [the cluster design](cluster-design.md):

- N1, the zero-load latency closed forms;
- N2, the resource-demand bounds;
- K3a, the memory theorem;
- the exactness of the `periodic_state` fast-forward engine.

For each result it also lists the test that checks the statement against the exact
event evaluator.

**Status of the claims.**
- Every result here is *exact under the stated abstraction* of the design (blocking cores
  and banks, XY routing with virtual cut-through, line-interleaved banks, one FIFO memory
  controller). None of it is a hardware claim. The selected L4R5 board is single-core,
  and this cluster is synthetic.
- A *proof* establishes the statement for all parameters in its domain. A *check* is a
  test against the evaluator on finitely many configurations. Each section says which is
  which.
- The evaluator itself is checked against an independent tick oracle (300 random
  clusters, `tests/cluster_tests.cpp`).

**Notation.** All times are integer cycles.

| Symbol | Meaning |
|---|---|
| `k` | grid side; `B = k²` tiles = banks |
| tile `i` | coordinates `(i mod k, i div k)` |
| `t_r`, `t_l` | router delay; link cycles per flit (`t_l ≥ 1`) |
| `f` | flit payload bytes |
| `F(b) = 1 + ⌈b/f⌉` | flits of a packet carrying `b` bytes |
| `L1`, `L2` | line sizes, with `L2 = r·L1` |
| `D` | memory latency of one L2 line: `L + (b−1)τ`, with `b = ⌈L2 / beat_bytes⌉` beats, first-beat latency `L`, beat time `τ` |
| `I` | memory issue spacing: `max(J₀, bτ)` |
| `K` | memory credits (outstanding requests) |
| `Z` | core compute time between reads |
| `P` | number of request sources |
| `m` | the memory-controller tile |

## 1. Network geometry

**Lemma 1.1 (XY hop count).** Under XY routing the path from tile `a` to tile `b` has

```text
H(a, b) = δ(x_a, x_b) + δ(y_a, y_b),
```

where `δ(u, v) = |u − v|` on a mesh and `δ(u, v) = min(d, k − d)` with `d = |u − v|` on a
torus.

*Proof.* XY routing makes all X moves in the source row, then all Y moves in the
destination column. The two dimensions are independent, so the path length is the sum of
the per-dimension lengths. On a mesh each dimension can only move straight toward the
target, which takes `|u − v|` steps. On a torus each dimension takes the shorter ring
direction (the + direction on a tie at `k/2`), which takes `min(d, k − d)` steps. ∎

*Check.* `tests/noc_tests.cpp` compares every route against breadth-first search for
mesh k = 2–8 and torus k = 3–8. `analytic::hops` recomputes the distance per dimension
and equals the routed length for the same range (`cluster_theorem_tests: hop_sums`).

**Proposition 1.2 (per-tile hop sum).** For a tile `c = (x, y)`,

```text
Σ_h H(c, h) = k·(S(x) + S(y)),
S(a) = a(a+1)/2 + (k−1−a)(k−a)/2     (mesh),
S(a) = ⌊k²/4⌋                         (torus).
```

The sum runs over all `k²` tiles `h`.

*Proof.* By Lemma 1.1 the sum splits into an X part and a Y part. In the X part each
value `x'` appears once per row, so the X part is `k·Σ_{x'} δ(x, x')`, and likewise for
Y. On a mesh, `Σ_{x'} |x − x'|` is the sum of the distances to the left, `1 + … + x`, plus
the sum of the distances to the right, `1 + … + (k−1−x)`. On a torus the multiset
`{min(d, k−d) : d = 0..k−1}` does not depend on `x`. Its sum is `2·Σ_{d=1}^{(k−1)/2} d =
(k²−1)/4` for odd `k`, and `2·Σ_{d=1}^{k/2−1} d + k/2 = k²/4` for even `k`; both equal
`⌊k²/4⌋`. ∎

**Corollary 1.3 (mean hop count).** Over all `k⁴` ordered (source, destination) pairs,
the self-pairs included, the mean hop count is

```text
mesh:   2(k² − 1)/(3k)
torus:  k/2 for even k,  (k² − 1)/(2k) for odd k.
```

*Proof.*
- **Mesh.** Summing Proposition 1.2 over all `c` gives `k·2k·Σ_x S(x)`. Then
  `Σ_x S(x) = Σ_{x,x'} |x − x'| = 2·Σ_{d=1}^{k−1} d(k − d) = k(k² − 1)/3`. So the total
  is `2k³(k² − 1)/3`, and dividing by `k⁴` gives `2(k² − 1)/(3k)`.
- **Torus.** The total is `k²·2k·⌊k²/4⌋`, and dividing by `k⁴` gives `2⌊k²/4⌋/k`. ∎

*Check.* Exact integer cross-multiplication for mesh k = 2–8 and torus k = 3–8
(`hop_sums`, and earlier `noc_tests`).

**Proposition 1.4 (bank resonance).** A stream whose L2 line numbers are
`ℓ₀ + iσ (i = 0, 1, …)` visits exactly `B / gcd(σ, B)` distinct banks, each equally
often over any `B / gcd(σ, B)` consecutive accesses.

*Proof.* The bank is `(ℓ₀ + iσ) mod B`. The values `iσ mod B` form the cyclic subgroup of
`ℤ_B` generated by `σ`. That subgroup is generated by `g = gcd(σ, B)` and has `B/g`
elements. The stream visits the coset `ℓ₀ + ⟨g⟩` and cycles through it with period
`B/g`, visiting each element once per cycle. ∎

For `σ = B` every access goes to one bank. Section 3 uses this to make the bank bound
binding.

*Check.* `noc_tests` (resonance formula) and the N2 resonance regime below.

## 2. N1: zero-load latency

**Lemma 2.1 (zero-load packet time).** A packet of `F` flits is injected at its source
router at time `τ` and travels `H ≥ 1` hops. If it never waits for a link, it is
delivered at

```text
τ + T₀(H, F),    T₀(H, F) = H(t_r + t_l) + (F − 1)t_l.
```

A local packet (`H = 0`) is delivered at `τ`: it has no network cost (BK2).

*Proof.* The head becomes ready for its first link after the source router's `t_r`, so
the first grant is at `τ + t_r`. Under virtual cut-through each later grant comes `t_l`
(link crossing) plus `t_r` (next router) after the previous one. The last grant is
therefore at `τ + t_r + (H−1)(t_l + t_r)`. The last link is held for `F·t_l`, and the
packet is delivered when its last flit leaves, at `τ + t_r + (H−1)(t_l + t_r) + F·t_l =
τ + H(t_r + t_l) + (F−1)t_l`. ∎

**Theorem 2.2 (N1).** Consider a read of one L1 line by the core on tile `c`, whose home
bank is `h`. Suppose every bank, every link and the memory controller it uses are idle
when it reaches them. Then its latency is:

```text
L1 hit:  λ₁ = lookup₁
L2 hit:  λ₂ = lookup₁ + T₀(H(c,h), F(0)) + lookup₂ + T₀(H(h,c), F(L1)) + fill₁
L2 miss: λ₃ = λ₂ + T₀(H(h,m), F(0)) + D + T₀(H(m,h), F(L2)) + fill₂
```

Here `T₀(0, ·) = 0`.

*Proof.* The read is a chain of steps, each starting when the previous one ends. Under
the idleness assumption, no step waits:
1. the L1 lookup;
2. the REQ (no payload);
3. the bank lookup;
4. on a miss: the MREQ, the memory service (admitted at arrival, done after `D`), the
   MRESP carrying the L2 line, and the L2 fill;
5. the RESP carrying the L1 line;
6. the L1 fill.

Each network step takes `T₀` by Lemma 2.1. The other steps have the fixed durations
given. ∎

**Proposition 2.3 (a lone core is at zero load).** A single blocking core meets the
conditions of Theorem 2.2 on every read when `J₀ ≤ L` and `τ ≤ L`.

*Proof.* A blocking core has at most one read in flight. Every packet, bank operation and
memory operation of a read finishes before the core issues its next read. A bank becomes
free when it sends its RESP, and the core's next REQ arrives strictly later. The memory
needs more care, because of issue spacing. If memory admits a request at `s`, the next
admission may start at `s + I`. That next miss of the core cannot reach memory before
`s + D` (and in fact later). Then `I = max(J₀, bτ) ≤ D = L + (b−1)τ` holds when
`J₀ ≤ L` and `bτ ≤ L + (b−1)τ`, that is `τ ≤ L`. With only one request in flight, credits
never bind. ∎

**Corollary 2.4 (sum over banks).** For the core on tile `c = (x, y)`:

```text
Σ_h λ₂(c, h) = B(lookup₁ + lookup₂ + fill₁) + 2(t_r + t_l)·k(S(x) + S(y)) + (B − 1)(F(L1) − 1)t_l.
```

Divided by `B`, this is the mean L2-hit latency for a uniformly distributed line.

*Proof.* `T₀(H, F) = H(t_r + t_l) + (F−1)t_l·[H ≥ 1]`. The first part is linear in `H`,
and the sum of `H` over banks is given by Proposition 1.2 (paths have the same length in
both directions). The indicator is 0 for exactly one bank, the local one. So the
`(F−1)t_l` term appears `B − 1` times, not `B` times: `T₀` is not affine in `H`. ∎

*Check (N1).* `zero_load_vs_evaluator` covers 2×2, 3×3 and 4×4 meshes and 3×3 and 4×4
tori, with 6 random timing configurations each and every core tile: 324 single-core runs
and 25,476 reads. Each stream mixes L1 hits, L2 hits and cold misses across every bank.
Every latency equals Theorem 2.2, and every per-tile sum of L2 hits equals Corollary 2.4.
A mutation that replaces `t_l` by `t_r` in `T₀` fails on the first read.

## 3. N2: resource-demand bounds

Fix a finite workload whose reads have known classes (L1 hit, L2 hit or L2 miss) and
known home banks. Every read then places a fixed, timing-independent demand on the
resources:
- **L1 hit:** nothing outside its core.
- **L2 hit:**
  - a REQ (`F(0)` flits) on each link of the XY path core→bank;
  - a RESP (`F(L1)` flits) on each link of bank→core;
  - bank time `lookup₂`.
- **L2 miss:**
  - the L2-hit packets;
  - an MREQ (`F(0)`) on bank→`m` and an MRESP (`F(L2)`) on `m`→bank;
  - one memory request;
  - bank time of at least `β = lookup₂ + T₀(H(h,m), F(0)) + D + T₀(H(m,h), F(L2)) + fill₂`.
    A blocking bank (BK1) is busy from its grant until the RESP is sent.

**Lemma 3.1 (no read beats zero load).** In any execution, each read's latency is at
least its zero-load latency `λ` from Theorem 2.2.

*Proof.* Follow the read's chain of steps. Each step starts no earlier than the previous
one ends, and contention only adds non-negative waits:
- link grant ≥ ready;
- bank grant ≥ arrival;
- memory admission ≥ arrival.

Each step's own duration is unchanged. By induction along the chain, every step ends no
earlier than in the zero-load timing. ∎

**Theorem 3.2 (makespan lower bound).** Let `T` be the last completion time over all
cores. Then `T` is at least each of the following:

```text
core p:   start_p + Σ_{reads of p} (Z_p + λ)
link ℓ:   t_l · (flits crossing ℓ)
bank b:   Σ_{L2 hits at b} lookup₂ + Σ_{L2 misses at b} β
memory:   (N − 1)·I + D   and   ⌈N/K⌉·D       (N = memory requests ≥ 1)
```

*Proof.* Each bullet is a different resource.
- **Core.** A blocking core issues read `j+1` exactly `Z_p` after read `j` completes,
  and its first read `Z_p` after `start_p`. Apply Lemma 3.1 to every read.
- **Link.** A link serves one packet at a time, for `F·t_l` cycles each. Every
  occupancy interval ends before its packet is delivered, which is before its read
  completes, so all of them lie in `[0, T]`.
- **Bank.** A bank serves one request at a time, and its busy intervals end no later
  than its RESP. Hit intervals last `lookup₂`. Miss intervals last at least `β`, by
  Lemma 2.1 applied to the MREQ and MRESP plus the memory latency `D`.
- **Memory, issue spacing.** Consecutive admissions are at least `I` apart, because
  `next_issue = start + I`. So the last admission is at least `(N−1)I`, and it completes
  `D` later, before the read it serves.
- **Memory, credits.** Label each admission with a credit slot. Its own slot is free if
  fewer than `K` requests are outstanding; otherwise it takes the slot of the earliest
  completion, which it must wait for. Requests on the same slot do not overlap, and each
  holds its slot for `D`. Some slot serves at least `⌈N/K⌉` requests, so that slot's
  last completion is at least `⌈N/K⌉·D`. ∎

In throughput form, for long periodic runs with `P` cores, per-core round-trip time `R₀`
and largest per-request demand `D_max` on any single resource, this is the classical
asymptotic bound `X ≤ min(P/(Z + R₀), 1/D_max)` [Lazowska et al. 1984, ch. 5].

**Proposition 3.3 (all-to-all channel load on a mesh).** Suppose every tile of a k×k
mesh sends one packet to every tile (including itself) under XY routing. Then the most
loaded directed link carries `k⌊k²/4⌋` packets: `k³/4` for even `k` and `k(k²−1)/4` for
odd `k`. The maximum is reached on the bisection links.

*Proof.* Take the `+x` link from column `x` in row `y`. The packets on it are exactly
those whose source is in row `y` at a column `≤ x` and whose destination column is
`> x`, with the destination row arbitrary: X moves happen in the source row. That is
`(x+1)·(k−1−x)·k` packets. Y moves happen in the destination column, so the `+y` link
from row `y` carries `k(y+1)(k−1−y)` packets. The `−x` and `−y` links mirror these. The
product `(x+1)(k−1−x)` is largest at the middle, where it equals `⌊k/2⌋⌈k/2⌉ = ⌊k²/4⌋`.
∎

This is the standard bisection-limited load for dimension-order routing [Dally & Towles
2004, ch. 3].

*Check.* Analytic XY paths (stepped independently of `noc::Topology`) equal the routed
paths, and the maximum all-to-all load equals `k⌊k²/4⌋` for mesh k = 2–8
(`channel_load`).

**Lemma 3.4 (classes by construction).** The N2 test needs read classes that do not
depend on how cores interleave. Two facts provide them.
- **(a)** Under LRU, if a set is accessed cyclically over `n > W` distinct lines, every
  access misses.
- **(b)** If a cache's sets each receive at most `W` distinct lines in total, nothing is
  ever evicted. Then the misses are exactly the first touches, in any order.

*Proof.*
- **(a)** Between two accesses to a line `x`, the other `n − 1 ≥ W` lines of the set are
  each accessed. This pushes `x` to LRU depth at least `W`, so it has been evicted.
- **(b)** A set never holds more than its `W` lines, so an install never evicts. A line
  that has been installed therefore stays, and only first touches miss. ∎

The N2 test streams use (a) for private L1s: half-line pairs, with each L1 set seeing
more than `W₁` lines cyclically. They use (b) for the shared L2: disjoint contiguous
blocks of at most `B·S₂·W₂` lines.

*Check (N2).* `demand_vs_evaluator` runs 150 random clusters in three regimes: random,
link-heavy, and stride-`B` bank resonance (Proposition 1.4). The predicted per-link
packet and flit counts, link busy cycles, bank references and misses, memory requests
and L1 hits and misses equal the evaluator's exactly. Every bound of Theorem 3.2 holds.
A mutation that adds one cycle per read to the core bound fails. Every term binds in some
clusters. The observed tightness is listed in design §6 N2: it is a measurement, not part
of the theorem.

## 4. K3a: the memory theorem

**Setting.** `P` sources are attached directly to the memory service, with no network.
Each source has constant compute `Z ≥ 0` and requests one aligned L2 line, so every
request has latency `D` and issue spacing `I ≥ 1`; the service has `K ≥ 1` credits.
Requests are submitted in arrival order, with ties broken by source index. That is also
round-robin with its pointer at 0. Source `p`'s first request arrives at `Z`, and each
later one arrives `Z` after its previous completion.

**Service rule** (`MemoryService::submit`, `src/service.cpp`). A request arriving at `a`
is handled as follows:
1. Set `start = max(a, next_issue)`.
2. Release every pending completion `≤ start`.
3. If `K` completions are still pending, set `start` to the earliest of them and release
   again.
4. Record `done = start + D` and `next_issue = start + I`.

A completion at a tick therefore frees its credit for an admission at that same tick.

**Theorem 4.1 (K3a).** Number the admissions `n = 0, 1, …`. Then:
1. Admission `n` serves source `n mod P`.
2. The admission times satisfy

   ```text
   s_n = max(a_n, s_{n−1} + I, s_{n−K} + D),
   a_n = Z (n < P),   a_n = s_{n−P} + D + Z (n ≥ P),
   ```

   with terms of negative index omitted.
3. `lim s_n / n = λ = max(I, D/K, (Z + D)/P)`. The throughput is exactly
   `X = 1/λ = min(1/I, K/D, P/(Z + D))`.
4. The sequence is eventually periodic: there are `n₀` and `c` with
   `s_{n+c} = s_n + cλ` for all `n ≥ n₀`.
5. The mean response time over a period is `R = Pλ − Z`.

*Proof of 1 and of the arrival formula.* We use induction on `n`.
- Admissions are strictly increasing, because `s_n ≥ s_{n−1} + I` with `I ≥ 1`. So
  completions `s_n + D` are strictly increasing.
- Assume admissions `0..n−1` served sources `0..n−1 mod P`. Source `j mod P`'s next
  request arrives at `s_j + D + Z`. These arrival times increase with `j`, and all of
  them exceed `Z`, the arrival time of the first `P` requests (since `s_0 ≥ Z` and
  `D ≥ 1`).
- So, ordered by arrival with ties broken by source, the requests are exactly the index
  order `0, 1, 2, …`. The `n`-th request arrives at `a_n` as stated and comes from source
  `n mod P`.

*Proof of 2.* The pending list holds at most `K` completions, because a full list forces
a release before the insert. Pending entries are only ever removed from the front, so
before admission `n` the list is a set of most recent completions
`{s_j + D : n−K ≤ j ≤ n−1}`, possibly with some of the oldest already released. Let
`t = max(a_n, next_issue) = max(a_n, s_{n−1} + I)`. There are two cases.
- **All `K` entries remain after releasing those `≤ t`.** This includes
  `s_{n−K} + D > t`. The service starts at the earliest entry, `s_{n−K} + D`, which
  equals `max(t, s_{n−K} + D)`.
- **Fewer than `K` entries remain.** The service starts at `t`. If `n < K` there is no
  credit term. If `n ≥ K`, the entry `s_{n−K} + D` has been released, either at an
  earlier admission (whose start is at most `s_{n−1} < t`) or now. Either way
  `s_{n−K} + D ≤ t`, so `t = max(t, s_{n−K} + D)`.

*Proof of 3.* For `n ≥ M = max(P, K)` the recurrence is homogeneous:
`s_n = max_j (s_{n−j} + w_j)`, with weights `w_1 = I`, `w_K = D` and `w_P = D + Z` (the
two latter merge as `max` when `K = P`).
- **Lower bound.** For each lag `j`, `s_n ≥ s_{n−j} + w_j`, so `s_{n₀ + qj} ≥ s_{n₀} +
  q·w_j`. Hence `liminf s_n/n ≥ w_j / j` for every `j`, and so `≥ λ`.
- **Upper bound.** Let `C = max_{i<M} (s_i − iλ)`. If `s_i ≤ C + iλ` for all `i < n`,
  then `s_n = max_j (s_{n−j} + w_j) ≤ max_j (C + (n−j)λ + w_j) ≤ C + nλ`, since
  `w_j ≤ jλ` by the definition of `λ`. So `s_n ≤ C + nλ` for all `n`, and
  `limsup s_n/n ≤ λ`.

Both bounds give `lim s_n/n = λ`. Each source completes one request per `P` admissions,
so the throughput is `1/λ`. ∎

*Proof of 4.* The state vector `x_n = (s_n, …, s_{n−M+1})` evolves as `x_n = A ⊗ x_{n−1}`
in the max-plus algebra. `A` is a companion matrix: shifts on the subdiagonal and
weights `w_j` in the first row. The lag `M` weight is finite (it is `w_K` or `w_P`), so
the precedence graph of `A` is strongly connected: `A` is irreducible. Its unique
eigenvalue is the maximum cycle mean. The elementary cycles of a companion graph each
use one first-row arc of lag `j` and `j − 1` shifts, so their means are exactly `w_j/j`.
The maximum is `λ`, matching part 3. The cyclicity theorem for irreducible max-plus
matrices [Baccelli et al. 1992, ch. 3; Heidergott, Olsder & van der Woude 2006, ch. 3]
then gives `n₀` and `c` with `x_{n+c} = cλ ⊗ x_n` for `n ≥ n₀`. Part 4 follows: `x_M` is
finite, so the inhomogeneous start (`n < M`) only affects the transient. ∎

*Proof of 5.* Let `R_n = s_n + D − a_n` be the response time of request `n`. Then
`a_{n+P} − a_n = R_n + Z`. Sum this over `q` consecutive `n` in the periodic regime,
where `a_{j+q} = a_j + qλ` by part 4. The left side telescopes:
`Σ_{j=n}^{n+q−1} (a_{j+P} − a_j) = Σ_{i=0}^{P−1} (a_{n+q+i} − a_{n+i}) = Pqλ`. So
`Σ R_j = q(Pλ − Z)`. ∎

**Open: transient length.** The theorem does not bound `n₀`. In the check below the
longest observed transient is 30 admissions, with `P ≤ 8`, so `n₀` is not bounded by
`P`. Max-plus transient bounds exist in general [Hartmann & Arguelles 1999] but are loose.
A tight bound for this companion structure is an open item.

*Check.* `k3a` drives the production `MemoryService` with `P` closed-loop sources through
an event loop that never uses the recurrence. In 3,000 random configurations × 600
admissions:
- every admission equals the recurrence;
- sources stay in cyclic order;
- the tail is periodic with slope `λ` (exact rational arithmetic);
- the mean response over a period is exactly `Pλ − Z`.

Every term of `λ` binds in some cases (issue 890, credits 612, sources 1,498). A worked
example, `P=4, Z=10, D=12, I=2, K=2`, gives admissions `10, 12, 22, 24, 34, 36, …`, so
`λ = 6` and `R = 14`. Removing the credit term from the recurrence fails the example.

**Scope.** K3a describes memory alone. In the full cluster it applies when every read
misses L2 and the network and banks are off the critical cycle. Theorem 3.2 decides
which resource dominates; that is never assumed.

## 5. Exactness of the `periodic_state` engine

The engine (design §5, `src/cluster.cpp`) evaluates events as `finite` does. At
checkpoints it forms a normalized key `N_T(S)` of the state `S` at time `T`, where every
event before `T` has been processed. When a key repeats, it skips whole periods. This
section proves that skipping changes nothing in the results.

**Lemma 5.1 (no tie is decided by ids or sequence numbers).** Packet ids and arrival
sequence numbers never decide an arbitration, and the order in which same-tick
deliveries are handled does not matter.

*Proof.* Consider each place a tie could be broken.
- **Links.** An id is reached only after `(ready, input port, class rank)` are equal.
  Packets on a non-local input port come from one upstream link. That link grants at
  most one packet per tick, and each packet's ready time is its grant time plus the
  constant `t_l + t_r`. So two packets on the same non-local port never share a ready
  time. On the local port each tile injects at most one packet per class per tick:
  - the core has at most one read in flight, and its REQs are strictly ordered in time;
  - the bank injects at strictly increasing times, because a hit's RESP comes
    `lookup₂ ≥ 1` after its grant, a miss's MREQ also `lookup₂` after its grant, the
    fill's RESP ends the busy interval, and the next grant is no earlier than that;
  - the memory controller's MRESPs are `D` after admissions that are at least `I ≥ 1`
    apart.

  The classes have distinct ranks, so no tie reaches the id.
- **Banks.** These order by `(arrival, source)`, or by `(source, arrival)` under
  fixed priority. Two requests from one source cannot share an arrival, because a core
  has one read in flight.
- **Memory controller.** It orders by `(arrival, bank)`, and a blocking bank has at most
  one miss outstanding.
- **Same-tick deliveries.** These touch disjoint state (different cores, or one bank's
  MRESP and REQs), except for queue insertions. Queue insertions are ordered by the keys
  above, so the handling order is irrelevant. ∎

*Check.* The tick oracle breaks residual ties by *reverse* id and agrees with the
evaluator on 300 random clusters. A real bug of this kind (same-tick local ties falling
back to id) was found this way and fixed by adding class ranks (commit `8b3548d`).

**Lemma 5.2 (translation invariance).** Let `S + Δ` be the state `S` with every stored
time increased by `Δ`. The evaluator's step from `S + Δ` gives the step from `S`, shifted
by `Δ`. The counter increments are identical.

*Proof.* Every rule of the model either compares two times, takes `max` of times, or adds
a configured constant to a time. All of these commute with adding `Δ` to every time.
Every counter increment is either a constant or a difference of two times:
- latency `= done − issue`;
- link wait `= grant − ready`;
- bank and memory waits;
- bank busy time `= respond − granted`.

None of these changes under translation. ∎

**Lemma 5.3 (the clamps are exact).** Suppose two states agree except in values that the
key clamps or drops at `T`. Then they have identical futures from `T` on.

*Proof.* There are three kinds of clamped or dropped values.
- **Link and bank free times.** These enter only through `grant = max(free, earliest
  ready)`. Every event before `T` is processed, so no grant time is below `T`. Hence a
  free time `≤ T` acts exactly as `T`.
- **Memory.** Every admission happens at a grant tick `s ≥ T`. It starts at
  `max(s, next_issue)` and releases every completion `≤ start`. So a `next_issue ≤ T` and
  any completion `≤ T` cannot affect an admission.

  The controller's grant time is `G = max(E, A)`, where `E` is `earliest_admission` and
  `A` is the earliest queued arrival. Let `n = next_issue` and `𝒫` the pending
  completions; the key keeps `n' = max(n, T)` and `𝒫' = {p ∈ 𝒫 : p > T}`. By definition,
  `E` is `n` if fewer than `K` entries of `𝒫` exceed `n`, and otherwise the smallest
  entry above `n`. Since all events before `T` are processed, `G ≥ T` whenever a request
  is queued. There are three cases.
  - **`n ≥ T`.** The entries above `n` are the same in `𝒫` and `𝒫'`, so `E' = E`.
  - **`n < T` and fewer than `K` entries above `n`.** Then `E = n < T`, so `G ≥ T` forces
    `A ≥ T` and `G = A`. The clamped state has at most as many entries above `n' = T`,
    so `E' = T` and `G' = max(T, A) = A`.
  - **`n < T` and `K` entries above `n`.** Then `E` is the smallest of them.
    - If `E > T`, those entries are all above `T` and survive in `𝒫'`, so `E' = E`.
    - If `E ≤ T`, then `𝒫'` has fewer than `K` entries and `E' = T`. If `A ≥ T`, both
      grant times equal `A`. If `A < T`, then `G ≥ T` forces `E = T`, and both grant
      times equal `T`.
- **Sequence numbers and packet ids.** These are dropped by Lemma 5.1. ∎

**Theorem 5.4 (skip exactness).** Suppose checkpoints at `T₁ < T₂` have equal keys.
Let `Δ = T₂ − T₁`, and let `d_p` be core `p`'s reads in `[T₁, T₂)`.
- **No finished core advances.** A finished core has `d_p = 0`.
- **Every unfinished core advances.** An unfinished core has `d_p > 0`.

Let `q` be the largest integer such that every unfinished core still has an unread
read after `q` more periods. Then for every `m ≤ q`, the true state at `T₂ + mΔ`
normalizes to the same key. The engine sets it to:

```text
S(T₂) + mΔ,   read index_p + m·d_p,   every counter + m·(counter(T₂) − counter(T₁)).
```

Every final result equals the finite run's, except that skipped reads are counted, not
listed.

*Proof.* By Lemmas 5.1 and 5.3, equal keys mean `S(T₂)` and `S(T₁) + Δ` have identical
futures. By Lemma 5.2, the evolution from `S(T₁)` over `[T₁, T₂)` translates to the
evolution from `S(T₂)` over `[T₂, T₂ + Δ)`, with identical counter increments. Iterating
`m` times gives the stated state.

The key records each core's read index modulo `address_period`, so `d_p` is a multiple
of the period: the address stream repeats too. The finite-count run equals the unbounded
periodic run as long as no core reaches its count. That is ensured by `m ≤ q`.

Minimum and maximum latency are unchanged, because the skipped reads repeat the
latencies of the reads evaluated in `[T₁, T₂)`. After the skip the engine continues with
ordinary events, which are exact. ∎

**Remark (why `m = q − 1`).**
- **Memory active during the period.** Key equality says nothing about *dead* credits
  (completions `≤ T` that the service still lists until its next admission). These are
  part of the reported final state. The engine skips `q − 1` periods and evaluates at
  least one whole period afterwards, so the first admission in it prunes the dead credits
  exactly as the finite run does.
- **Memory idle during the period.** Its state is literally unchanged and is not
  shifted.

The reported memory state therefore equals the finite run's literally, not just up to
normalization.

**Remark (no false positives).** Keys are compared as complete byte strings, not
hashes. Every variable-length part is prefixed by its length and offsets are stored
modulo `2⁶⁴`, so the encoding is injective while offsets stay below `2⁶³`. A repeat
detected is a true repeat.

**Termination.** Theorem 5.4 is about exactness, not about whether a repeat ever happens.
A periodic regime is not guaranteed. Under `fixed_priority` a low-priority core's request
can wait indefinitely if higher-priority cores keep its bank busy. Its arrival offset
then falls without bound, so no key ever repeats and the engine never skips. The engine remains exact in that case. The stored keys are
capped at 64 MiB and the event budget still applies, so a run that does not repeat in
time fails explicitly instead of running forever. Even when a periodic regime exists,
nothing here bounds when it starts (see the 4×4 example below).

*Check.*
- In 120 random clusters, `periodic_state` equals `finite` on every counter, the final
  L1, L2 and memory state, and every listed read. 111 of them skipped.
- A run of `10⁹` reads of one address matches its closed form. Read `k` completes at
  `10 + 76 + 11k` (a cold miss of 76 cycles, then L1 hits of 1 cycle with compute 10).
  The run evaluates 4 reads.
- The 4×4 example is a cautionary case. Its first repeat comes after about 976,000
  evaluated reads; after that the period is 256 reads.

## 7. Not covered here

- **Transient lengths.** Neither K3a nor periodic repetition has a proven bound on when
  periodicity starts.
- **Tightness of the N2 bounds.** This is observed, not proven.
- **N4.** Queueing approximations (M/D/1 per channel, MVA) are a stretch item. They will
  be reported as approximations, with errors against this exact model.
- **N5.** Fixed-priority fairness is an experiment with no closed form.
- **Hardware.** The cluster is not validated against hardware. The physical target is
  single-core.
